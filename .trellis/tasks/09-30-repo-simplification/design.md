# 技术设计：全仓冗余精简

## 边界

按父 PRD 分成应用/工具 A 与 Trellis 基础设施 T 两条可独立验证的变更。应用入口与框架入口保持原路径；不更改平台注册配置、`.template-hashes.json`、全局安装或音频算法。

## 方案

### A：优先移除第二套实现

- WordPress 已提供特色图片能力。删除插件重复封面 HTML、JS 和手动 `_thumbnail_id` 保存段，保留原生 `postimagediv`、音频字段、自动识别及前台封面回退。
- 删除两个死查询/渲染 helper；播放别名的唯一调用点直接转到 `dj_track_button()`。
- 只删除紧凑模式那个永久隐藏的封面 img 及其写入分支，不碰 `data-jog-cover`、曲库图片或 `MediaMetadata.artwork`。
- 公共按钮色彩集中到同等 specificity 的 `:is()` 规则；hover/active 各自保留 transform，其他外观和交互不动。
- 检查器用原生目录枚举；不扩展成扫描框架，也不引入 glob 依赖。通过旧/新覆盖集合比较验证等价性。

### T：原路径薄入口＋项目内共享实现

- 新共享模块放在 `.trellis/scripts/hooks/`：`shared_subagent_context.py`、`shared_session_start.py`、`shared_workflow_state.py`。
- 七个原始脚本保留，仅负责从脚本位置定位共享目录、import、调用 `main()`。不改 `sys.argv`，不通过 runpy 把平台路径替换成共享模块路径。
- 除去确认无调用的 `run_script()`，先保持共享实现原样搬移，避免将“去重”变成协议重写。
- Codex 独有的 SessionStart 和 Cursor shell bridge 保留，不强行纳入公共实现。
- CLIAdapter 只有模板注册等非执行引用，复核当前消费者后删除生成模块；不删除其模板哈希记录。

## 数据和协议

- 音轨 REST 字段、WordPress 元数据键、播放器 DOM 标记和事件动作不变；只允许删除审计明确列出的无消费者节点/符号。
- Hook 仍从 stdin 接收原负载，输出相同 stdout 格式与退出状态。编码、平台探测、上下文限制、路径包含校验和错误行为保留。
- 新共享模块依赖项目文件，不依赖 npm 安装位置；不同 cwd 和带空格路径必须可用。

## 更新兼容

Trellis 0.6.17 的更新器已支持用户修改/删除保护，见研究文档。本任务不“修正”哈希记录：原值用于识别本地改动和用户删除。升级先 `trellis update --dry-run`，对定制入口选择保留或生成 `.new` 后审阅。

此方案保留现有平台入口，减少本仓代码副本；不追求把上游项目也改成相同架构。不新增自动打补丁、空文件墓碑或升级守护脚本。

## 验证与风险

- 同一输入在原始/精简入口间做差分回放，必须比较完整协议和失败边界，不能只测 import 成功。
- 用隔离 fixture 承载会话和任务状态，防止测试污染真实 `.trellis/.runtime`、日记或当前任务。
- 原生 WordPress 封面是本任务唯一有意改变的后台呈现位置；功能验证与纯语法检查分开记录。
- 新测试代码计入净行数，不为达到估计削减量裁掉必要边界或测试。

## 回退

每个子任务保留独立差异边界。T 回退时同时恢复七个入口及共享模块集合，A 回退时同步恢复相应 PHP/JS/CSS。只回退本任务改动，不接触 Spotify 修改、预览数据或历史资料。当前不安排生产发布。
