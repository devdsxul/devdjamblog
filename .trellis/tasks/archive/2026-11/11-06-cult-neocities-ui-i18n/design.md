## 推荐的体验

保留现有海报墙、烟黑标题栏、金属哥特字、GifCities 贴纸、日历、计数器与 Win98 方角窗口。把可读区域做成贴在海报上的纸条：正文、列表和表单有实底，空白与窗口边缘继续露海报；无需新增假标签或装饰文案。

顶部提供 Milk / Ink / Cherry 和 EN / 中文紧凑按钮；窄屏可折行，不压住最大化控件或底部任务栏。语言首次跟随浏览器，之后以手动选择为准。按实施中的最新反馈，右上角去掉动效按钮，动效继续由横幅眼球贴纸控制；展开打碟机在全部主题下使用亮色机箱、保留黑色读数屏；访客标题只在标题栏出现一次。

## 边界和任务组织

沿用 WordPress PHP 模板、原生 JavaScript、98.css 与现有文件布局。作为单一任务分阶段实施：语言契约、静态/动态出口、视觉、集成验收共用相同窗口与控件，拆独立子任务反而需要重复调整这些节点。

- 主题拥有 UI 文案与样式；`devdjam-core` 的内容模型、REST 数据结构、后台以及 DSP 不改。
- `#site-content` 为可替换区域；两只 audio 元素、音频引擎、播放器与全站偏好留在常驻壳中。
- 普通窗口的 `data-window` / `data-window-action`、拖拽/层叠、移动禁拖契约保持。小说专用对话框现有关闭/返回按钮保留。
- 不删未使用素材，不添依赖，不引入远程图片/字体，不重写海报文件。
- 原本地实施阶段不提交或部署；后续发布按用户追加授权执行。保留 `.playwright-mcp/` 等原有本地内容，不纳入提交或部署。

## 视觉规则

### 面板与色彩

扩充 `site.css` 现有变量，保留既有变量名的兼容含义，避免在文件尾堆叠第二套互相覆盖的样式系统。

| 角色 | 推荐处理 |
| --- | --- |
| 画布 / 海报 | 沿用桌面海报、窗口海报和压暗层；文字纸条外的留白保持透明。 |
| 内容实底 | Milk/Cherry 使用暖白纸色，Ink 使用深墨色；不通过逐层 alpha 叠加获得可读性。 |
| 正文 / 次要文字 | 各自独立语义色；实底上的正文目标 ≥7:1，小字 ≥4.5:1。 |
| 装饰强调 / 文字强调 | 粉色与 Cherry 红保持；装饰高亮和可读链接色分别定义，避免亮粉小字直接落在照片上。 |
| 选中 / 焦点 / 禁用 | 保持黑白反色、Win98 点线键盘焦点与现有状态语义；禁用不冒充可点。 |
| 硬件 | LCD/旋钮/唱盘保留独立深色读数与 LED；只统一字体、标注和共享控件，不改变输入几何。 |

内容纸条按语义块落底：文章正文整体、首页最新卡文字区、音乐/Beat 列表行、学习小组摘要、留言与表单。不要给窗口所有空白都铺实底，也不要给每个嵌套 span 单独铺底。标题栏保持烟黑方向，实测最亮海报位置下的文字可读性。

### 字体与组件

- 哥特字只承载品牌/进站门；界面使用一套像素/系统中英回退；数字、BPM、时长使用等宽；长文使用易读正文栈。
- 小说现有字号、宋体/黑体/等宽偏好是用户功能，保留，不因统一字体移除。
- 间距以现有 2 / 4 / 8 / 12 / 16 / 24px 为标尺。统一按钮、标签、列表分隔、字段、空状态和窗口内容内边距，保留有真实用途的尺寸差异。
- 共享控件方角、1px 线、硬阴影；圆形限硬件。移动表单仍 16px，关键触摸控件保持既有点击面积。
- 装饰 GIF 在 reduced-motion / 动效关闭时使用已有静态帧；仅关闭 CSS animation 不算停止 GIF。

## i18n 数据流与契约

### 一个独立入口

建议新增小型 `assets/i18n.js`，把当前中文字典、语言解析、静态标记翻译从音频 IIFE 中移出，放在 `window.DEVDJAM.i18n`。通过 WordPress 脚本依赖保证早于 `site.js` 可用；不另建框架或动态加载链。`DEVDJAM` 配置沿用 Object.assign 合并，不能覆盖翻译命名空间。

推荐流程：解析合法保存值 → 无保存值时按浏览器首选语言选 zh/en → 设置 `html.lang` / `data-lang` → DOM 可用后翻译静态节点 → 播放器/小说状态函数用同一 `t()` 输出当前文案。语言按钮由独立模块处理，音频加载失败仍可切换语言。

存储只接受 `zh|en`；无效值按首次访问处理，存储访问失败仍可在内存中切换。只在用户选择时保存语言，不把自动推断误存为显式偏好。头部早期语言逻辑与主脚本不能保留两套不同的默认规则；现有主题/进站门处理保留独立失败边界。

不承诺客户端偏好在无 JS 场景也生效。模板提供可读英文回退，不通过长期隐藏正文制造“无闪烁”；正常初始化后的文档语言和 UI 必须一致。无 JS 不新增阻断罩、不改变既有进入站点的约束。

### 翻译 API 与标记

- 兼容现有英文原文作为 key 的 `dj_text()` 与 `data-i18n`。中文缺键回退英文，同时由测试将应用自有缺键判为失败。
- `t(key, params)` 支持计数、百分比、曲名、页名等原样参数；用完整句子模板处理词序，不依靠中文/英文片段拼接。英文单复数按具体计数文案处理。
- 静态属性使用允许列表，例如 `data-i18n-aria-label`、`data-i18n-title`、`data-i18n-placeholder`、`data-i18n-alt`；动态范围数值文本覆盖 `aria-valuetext`。表单提交按钮只改显示 value，不改访客输入值。
- 文本写 `textContent`，属性写 `setAttribute`，不将翻译/插值写入 innerHTML；PHP 的键、参数与回退分别正确转义。
- `data-i18n` 仅放在文案叶节点，不能放在包含图标、其他控件或作者内容的容器。装饰图保持空 alt。
- 品牌名称（DEVDJAM、Spotify 等）和 DJ 硬件缩写（BPM、EQ、CUE、SHIFT、SYNC、FX 等）明确逐项记录；可访问名称中的动作说明仍翻译。

### 生命周期

翻译与状态渲染建立明确调用顺序，不用全站 MutationObserver 扫描每一次音频状态变化。

1. 首屏：静态标记翻译不依赖音频初始化。
2. 用户切换：翻译静态标记，更新现有播放器/队列/窗口/小说控件的显示文本；不能重新装载曲目、创建 AudioContext、改写 history、清空表单或重置阅读进度。
3. PJAX：沿用现有替换边界；初始化新视图后更新其翻译，窗口标题仍同步当前 `data-i18n`；载入/完成播报使用保留页名的模板。
4. 晚返回的数据与状态变化：队列、装载按钮、Hot cue、窗口按钮、动效提示、小说进度每次生成时都查当前语言；事件监听器不重复绑定。

### WordPress 输出

优先通过现有模板调用的局部参数/包装器为评论表单（含 cookies）、评论导航、分页补标记。日历由本地核心源码确认可用接口后标记月份/星期/前后月链接；日期元数据使用机器可读时间值，不从中英文字符串反推日期。仅调整表现，不改原查询、链接、权限或提交字段。

不做全局 gettext 替换，不替换整个页面文本，不全局切换站点 locale。前台 `<link type="application/rss+xml">` 的可访问标题属于界面元数据，应按可控入口补齐；RSS 文档本身、管理员工具栏和系统错误页不随客户端偏好翻译。作者内容、站名、文章/曲目/章节标题保持原样；学习小组固定栏目宣传文案与作者小说标题分开标记。

## 验证、风险与回退

细化顺序见 [implement.md](implement.md)。新 i18n 检查必须加载真实翻译模块，已有状态测试只是防回归。截图覆盖正文实底、两种语言与三套推荐主题；对比度来自最终 computed style / 实際底色而非文档宣称。模拟浏览器不等同于真机触摸、音频试听或生产验证。

主要风险是翻译覆盖破坏子 DOM、语言重绘重置播放器/阅读器、CSS 改动遮住模态按钮、WP 核心默认字段合并与旧存储值。按翻译基础 → 模板/状态 → 视觉分段修改并检查；每阶段检查工作区差异，只撤回明确属于本任务的具体修改，不运行 reset/clean。
