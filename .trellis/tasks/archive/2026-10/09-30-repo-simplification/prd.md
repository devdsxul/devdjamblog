# 全仓冗余精简

## 目标

落实用户确认的 ponytail 九项精简，减少重复实现和无消费者代码，同时保留 DJ Deck 功能、正常内容编辑以及 Claude Code / Codex / Cursor 的现有入口。

## 背景

- 起点：`main` 的 `e5d63f2`。`wp-content/themes/devdjam/index.php` 的 Spotify 修改独立保留，不属于本任务。
- 用户已要求“全部精简”并批准创建任务、进入规划；实施仍须等待最新规划摘要获得明确批准。
- 审计给出的约 4,900 行是候选估计，不是删行配额。最终扣除新共享入口与测试代码后报告实际净变化，不牺牲行为换数字。
- 当前 Trellis 与生成版本均为 0.6.17。该更新器会保留有原哈希记录的删除，并把定制文件当作冲突处理；本次无需修改上游源码或全局 npm 安装。证据见 [Trellis 研究](research/trellis-runtime.md)。

## 验收标准

- **AC1（R1/R4）**：代表性输入回放中，旧/新入口的平台识别、stdout 协议、退出行为与任务注入相同；覆盖非项目 cwd、含空格路径、UTF-8 和非目标事件。真实宿主检查另行标注。
- **AC2（R1/R2）**：保留 `.template-hashes.json` 基线不变，验证本地定制和删除保护；不以手改记录或强制覆盖伪造通过。
- **AC3（R2/R5/R9）**：运行代码中无被删符号的遗留消费者，文档、测试与调用点同步；模板基线记录不作为运行调用计算。
- **AC4（R3）**：两种音轨文章类型的原生特色图片流程可用，公开曲库封面字段、默认封面回退保持兼容。
- **AC5（R6/R8）**：控制台两盘、队列、播放状态反馈及锁屏媒体封面保持原有行为，删除范围不扩大到可见封面。
- **AC6（R7）**：原生枚举与旧检查器覆盖集合相同，包含嵌套目录及适用的非目录项；无效 PHP/JS 仍导致检查失败。
- **AC7（全范围）**：现有输入回归和新增针对性检查通过；未执行的浏览器、真机或平台宿主验收明确列为未验证，不用静态检查代替通过记录。
- **AC8（全范围）**：Spotify 修改独立保留；无新增依赖、全局安装改动、生产写入或未经授权的提交推送；报告实际净行数与依赖变化。
