# DEVDJAM 技术设计

用户已确认 WordPress。采用原生后台、独立内容插件、专属 PHP/CSS/JavaScript 主题，以及持久音频元素。

## 结构

- `wp-content/themes/devdjam/`：主题模板、CSS、前台导航、播放器、图像与装饰。
- `wp-content/plugins/devdjam-core/`：音乐分享与 beat 内容类型、元数据字段、媒体关联和只读播放列表接口。
- `dev/`：本地 WordPress Playground 启动和隔离测试配置。
- `deploy/`：服务器部署示例、音频上传限额和持久化配置。
- `docs/`：站主使用说明、视觉资源来源和验收报告。

## 内容契约

- 文章：标题、正文、摘要、封面、分类、草稿/发布状态与发布时间。
- 音乐分享：同类写作能力，归入独立音乐栏目，可使用 cloud rap / jerk rap 标签。
- Beat：标题、audio 媒体 ID、封面、介绍，可选 BPM、调性；未关联有效音频的记录不可进入播放队列。
- 链接、关于：由后台页面编辑器维护，初始正文留空。
- 未登录访客只读取已发布内容；所有写操作使用成熟 CMS 的认证能力。自定义表单同时检查 nonce、用户能力与输入类型。

## 页面与视觉

全站采用黑紫基调、低强度酸绿点缀、细边框、等宽正文、液态 DEVDJAM 标识、颗粒和拼贴。桌面使用页头 + 左侧栏 + 内容区；移动端收起装饰占位并重新排布栏目。装饰动效有限，遵守 prefers-reduced-motion；导航、播放器和表单可用键盘操作。

首页仍具有欢迎区、音乐区、beats 区、杂谈区和装饰条，但内容数据均为空。没有内容时显示短小、诚实的占位，不创建假文章、假歌曲或假访问量。

## 播放与导航

播放器使用单个 HTMLAudioElement，控制区在持久页面外壳中。前台点击本站导航时加载并替换内容区，维护地址栏、前进后退、标题、焦点与滚动。外链、下载、后台链接按普通浏览器行为处理，加载失败回退完整导航。

播放队列来自只读接口，仅含已发布且音频有效的 beat。状态包括空、加载中、暂停、播放和错误。首次无自动播放；用户点击后播放。自带播放/暂停、上/下一首、进度拖动、音量、队列和当前曲目信息。

## 部署与持久化

用户稍后自行部署。交付普通 WordPress 安装说明和可选 Docker Compose；数据库与 uploads 独立持久化。生产凭据由用户生成，示例中不写真实密钥。本轮不连接生产服务器。

## 验证边界

本地用官方 Playground CLI 跑真实 WordPress；检查桌面、手机、空状态、后台 CRUD、媒体上传、权限及播放器。测试用文章/音源放在隔离测试实例，交付初始实例仍为空。服务器 PHP + MariaDB、反向代理和 HTTPS 必须在最终部署环境另行核验。
